# Docker Compose a 4 servizi — piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `docker compose up -d --wait` avvia e attende sani `postgres`, `agente`, `backend`, `frontend`; la CLI resta con
`docker compose run --rm assistente`.

**Architecture:** Solo `compose.yaml`: nuovo servizio `frontend`, profilo `cli` per `assistente`, `healthcheck` in Python
per agente/back-end/front-end e `depends_on` con `service_healthy`. Un test senza Docker legge il file con PyYAML;
la prova reale con Docker e LM Studio è manuale.

**Tech Stack:** Docker Compose v5.7.0, PyYAML 6.0.3 (già fissato in `requirements.txt`), pytest.

**Spec:** `docs/superpowers/specs/2026-11-13-compose-design.md`

## Global Constraints
- Nessun codice Python di produzione nuovo, nessuna modifica a `Dockerfile`, nessuna dipendenza nuova.
- Ogni porta pubblicata con prefisso `127.0.0.1:`; porte 8000, 8001, 5433 invariate, nuova `127.0.0.1:8002:8002`.
- Controllo di salute: `["CMD", "python", "-c", "import urllib.request; urllib.request.urlopen('<url>', timeout=3)"]`
  con `interval: 5s`, `timeout: 5s`, `retries: 10`, `start_period: 10s`.
- URL: agente `http://127.0.0.1:8000/salute`, back-end `http://127.0.0.1:8001/salute`, front-end `http://127.0.0.1:8002/`.
- Un solo commit a fine step: `feat(compose): applicazione completa a 4 servizi con avvio in ordine di salute`, con
  trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Niente push. Fuori dallo stage: `lezione_3/`,
  `dati/`, `.env`, le cancellazioni fuori da `assistente-laboratorio/`.

## Review Focus
1. Il comando di salute deve fallire (uscita ≠ 0) con connessione rifiutata e con risposta 5xx, e riuscire con 200
   — se riuscisse sempre, `service_healthy` non attenderebbe nulla. Test in Task 1 che esegue il comando vero.
2. Un `.env` con `BACKEND_URL=http://127.0.0.1:8001` (valore locale) non deve valere nel container: `environment`
   prevale. Test in Task 1 sulle variabili del front-end; verifica reale in Task 2.
3. `docker compose run --rm assistente` deve funzionare nonostante il profilo. Prova reale in Task 2.
4. Con LM Studio spento la catena deve comunque diventare sana (salute = processo che risponde). Prova reale in Task 2.
5. Le conversazioni devono sopravvivere a `down` + `up` (volume `pgdati`). Prova reale in Task 2.
