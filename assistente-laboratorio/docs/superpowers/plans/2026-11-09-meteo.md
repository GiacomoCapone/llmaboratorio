# Meteo attuale (Open-Meteo): piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** aggiungere lo strumento `meteo_attuale`, che restituisce le condizioni meteo attuali di una
località interrogando Open-Meteo (geocoding + dati attuali).

**Architecture:** `strumenti/rete.py` fa GET JSON con `urllib` e traduce ogni guasto in `ErroreRete`;
`strumenti/meteo.py` contiene definizione, validazione, formattazione ed `esegui_meteo(args, scarica)`
con `scarica` iniettata; `crea_strumenti` lega `scarica_json` come predefinita. Grafo, CLI e config
restano invariati.

**Tech Stack:** Python 3.14, `urllib.request`/`urllib.parse`/`json` della libreria standard, pytest.

**Spec:** `docs/superpowers/specs/2026-11-09-meteo-design.md` (fonte di tutti i testi: definizione,
righe del risultato, tabella WMO, messaggi d'errore — copiarli alla lettera da lì).

## Global Constraints
- Nessuna dipendenza nuova; `requirements.txt` invariato.
- Lo strumento non solleva mai eccezioni: ogni errore è un testo che inizia con `Errore:`.
- Timeout 5 secondi; header `User-Agent: assistente-laboratorio`; nessun nuovo tentativo.
- Test automatici senza rete né modello; Open-Meteo vero solo con i marcatori `rete` e `reale`.
- Usare `.venv/Scripts/python.exe`; in Git Bash con input in pipe impostare `PYTHONIOENCODING=utf-8`.
- Conventional Commits in italiano; staging selettivo; mai in commit `.env`, `lezione_3/`,
  `docs/superpowers/2026-11-02-handoff.md`, né la modifica dell'utente a `CLAUDE.md` (vedi Task 4).
- Lavorare solo in `assistente-laboratorio/`, sul branch `feature`; nessun push.

## Review Focus
1. Località con lettere accentate o apostrofo (`Forlì`, `L'Aquila`): l'URL deve codificarle in UTF-8
   (`Forl%C3%AC`) e il messaggio «non trovata» deve riportarle intatte → test in Task 1 e Task 2.
2. Località con spazi intorno (`"  Trieste "`): al geocoding va `Trieste`, non la stringa grezza →
   test in Task 2.
3. Temperatura fra -0,05 e 0 (es. `-0.04`): la riga deve dire `0,0 °C`, non `-0,0 °C` → test in Task 2.
4. Timeout durante la lettura del corpo (non solo in `urlopen`): deve dare il messaggio di timeout,
   non un'eccezione → test in Task 1.
5. Corpo HTTP 200 vuoto: deve dare «risposta non valida» → test in Task 1.

### Task 1: modulo di rete

**Files:**
- Create: `src/assistente/strumenti/rete.py`
- Test: `tests/test_rete.py`

**Interfaces:**
- Produces: `class ErroreRete(Exception)` — `str(e)` è il testo del messaggio senza il prefisso
  `Errore: ` (es. `il servizio meteo ha risposto con stato 503.`);
  `scarica_json(url: str, parametri: dict) -> dict`; costanti `TIMEOUT_SECONDI = 5`,
  `USER_AGENT = "assistente-laboratorio"`.

I testi dei messaggi sono quelli della tabella «Errori» della specifica senza `Errore: `:
`servizio meteo non raggiungibile (<motivo>).`, `il servizio meteo non ha risposto entro 5 secondi.`,
`il servizio meteo ha risposto con stato <N>.`, `risposta del servizio meteo non valida.`

- [ ] **Step 1: scrivere i test** in `tests/test_rete.py`. Sostituire `rete.urllib.request.urlopen`
  con `monkeypatch.setattr` con una funzione finta che registra `(richiesta, timeout)` e restituisce un
  oggetto con `read()` e i metodi di context manager (oppure solleva l'eccezione voluta). Test:
  - `test_url_parametri_e_intestazioni`: `scarica_json("https://x.test/v1/search", {"name": "Forlì", "count": 1})`
    → `richiesta.full_url == "https://x.test/v1/search?name=Forl%C3%AC&count=1"`,
    `richiesta.get_header("User-agent") == "assistente-laboratorio"`, `timeout == 5`, metodo `GET`.
  - `test_restituisce_il_json`: corpo `b'{"a": 1}'` → `{"a": 1}`.
  - `test_stato_http`: `urllib.error.HTTPError(url, 503, "x", {}, None)` →
    `ErroreRete` con `str == "il servizio meteo ha risposto con stato 503."`.
  - `test_timeout_in_apertura`: `TimeoutError()` → `"il servizio meteo non ha risposto entro 5 secondi."`.
  - `test_timeout_come_motivo`: `URLError(TimeoutError())` → stesso messaggio.
  - `test_timeout_in_lettura`: `read()` solleva `TimeoutError` → stesso messaggio.
  - `test_non_raggiungibile`: `URLError("getaddrinfo failed")` →
    `"servizio meteo non raggiungibile (getaddrinfo failed)."`.
  - `test_corpo_non_json`, `test_corpo_vuoto`, `test_json_non_oggetto` (`b"[1]"`),
    `test_corpo_non_utf8` (`b"\xff"`) → `"risposta del servizio meteo non valida."`.
  - `test_guasto_registrato` (con `caplog`): un `HTTPError` produce un record `WARNING` del logger
    `assistente.strumenti.rete` che contiene `https://x.test/v1/search` e non contiene `Forl`.

- [ ] **Step 2: eseguire** `.venv/Scripts/python.exe -m pytest tests/test_rete.py -v` → FAIL
  (`ModuleNotFoundError`).

- [ ] **Step 3: implementare `rete.py`.** URL con `url + "?" + urllib.parse.urlencode(parametri)`;
  `urllib.request.Request(..., headers={"User-Agent": USER_AGENT}, method="GET")`;
  `with urllib.request.urlopen(richiesta, timeout=TIMEOUT_SECONDI) as risposta:` lettura dentro il
  `try`, così il timeout in lettura è intercettato. Ordine degli `except`: `HTTPError` (sottoclasse di
  `URLError`) → stato; `TimeoutError` o `URLError` con `reason` `TimeoutError` → timeout; altri
  `URLError` → non raggiungibile con `reason`; `OSError` → non raggiungibile con `str(e)`. Decodifica
  e JSON: `UnicodeDecodeError`, `json.JSONDecodeError`, oggetto non `dict` → non valida. Ogni ramo:
  `logger.warning("richiesta a %s fallita: %s", url, <tipo>)` con `logger = logging.getLogger(__name__)`
  e `raise ErroreRete(...) from e`.

- [ ] **Step 4: eseguire** `.venv/Scripts/python.exe -m pytest tests/test_rete.py -v` → tutti PASS;
  poi `.venv/Scripts/python.exe -m pytest` → 353 + i nuovi, nessun fallimento.

- [ ] **Step 5: commit**
```bash
git add src/assistente/strumenti/rete.py tests/test_rete.py
git commit -m "feat(strumenti): richieste JSON con urllib e errori di rete leggibili"
```

### Task 2: strumento meteo

**Files:**
- Create: `src/assistente/strumenti/meteo.py`
- Test: `tests/test_meteo.py`

**Interfaces:**
- Consumes: `ErroreRete` da `assistente.strumenti.rete` (Task 1).
- Produces: `DEFINIZIONE_METEO: dict` (nome `meteo_attuale`);
  `esegui_meteo(args: dict, scarica: Callable[[str, dict], dict]) -> str`;
  costanti `URL_GEOCODING = "https://geocoding-api.open-meteo.com/v1/search"`,
  `URL_PREVISIONI = "https://api.open-meteo.com/v1/forecast"`,
  `CAMPI_ATTUALI = "temperature_2m,apparent_temperature,relative_humidity_2m,precipitation,weather_code,wind_speed_10m,wind_direction_10m"`,
  `CODICI_WMO: dict[int, str]` (la tabella della specifica, 28 voci).

- [ ] **Step 1: scrivere i test** in `tests/test_meteo.py`. Fixture: `GEOCODING` e `ATTUALI` copiati
  dalle risposte vere riportate nella specifica (Pordenone, 45.95689/12.66051; `current` con
  `time "2026-11-09T09:00"`, 5.7, 4.1, 91, 0.0, 3, 1.5, 45; `timezone "Europe/Rome"`). Una classe
  `ScaricaFinta(risposte)` che registra `(url, parametri)` e restituisce le risposte in ordine (o
  solleva se la risposta è un'eccezione). Test:
  - `test_risultato_completo`: `esegui_meteo({"localita": "Pordenone"}, finta)` è uguale alla lettera al
    blocco di sette righe della sezione «Risultato» della specifica.
  - `test_parametri_inviati`: prima chiamata `(URL_GEOCODING, {"name": "Pordenone", "count": 1, "language": "it", "format": "json"})`;
    seconda `(URL_PREVISIONI, {"latitude": 45.95689, "longitude": 12.66051, "current": CAMPI_ATTUALI, "timezone": "auto"})`.
  - `test_localita_ripulita`: `"  Trieste "` → geocoding con `name == "Trieste"`.
  - `test_localita_mancante` parametrizzato su `{}`, `{"localita": None}`, `{"localita": ""}`,
    `{"localita": "   "}`, `{"localita": 42}` → `"Errore: indicare la località, per esempio Pordenone."`,
    nessuna chiamata a `scarica`.
  - `test_localita_troppo_lunga`: 101 caratteri → messaggio della specifica; 100 caratteri → chiama
    `scarica`.
  - `test_non_trovata` parametrizzato su `{"generationtime_ms": 0.1}` e `{"results": []}`, con
    `"L'Aquilaa"` → `"Errore: località non trovata: 'L'Aquilaa'."`.
  - `test_errore_di_rete`: `scarica` solleva `ErroreRete("il servizio meteo non ha risposto entro 5 secondi.")`
    al geocoding e, in un secondo caso, ai dati attuali → `"Errore: il servizio meteo non ha risposto entro 5 secondi."`.
  - `test_risposta_non_valida` parametrizzato: geocoding senza `latitude`; `latitude` `True`; `name`
    numerico; `current` assente; `temperature_2m` stringa; `timezone` assente →
    `"Errore: risposta del servizio meteo non valida."`.
  - `test_luogo`: senza `admin1` e `country` → `Luogo: Pordenone`; `name == admin1 == "Roma"`,
    `country "Italia"` → `Luogo: Roma, Italia`; `admin1 ""` omesso.
  - `test_codici_wmo`: per ogni voce di `CODICI_WMO` la riga è `Cielo: <descrizione>`; `len(CODICI_WMO) == 28`;
    codice 4 → `Cielo: condizione non classificata (codice 4)`.
  - `test_direzione_vento` parametrizzato: 0 → `nord`, 22.4 → `nord`, 22.5 → `nord-est`, 180 → `sud`,
    337.5 → `nord`, 360 → `nord` (riga `Vento: 1,5 km/h da <direzione>`).
  - `test_vento_calmo`: velocità 0 → `Vento: calmo (0,0 km/h)`.
  - `test_numeri`: temperatura -3.2, percepita 12 → `Temperatura: -3,2 °C (percepita 12,0 °C)`; temperatura -0.04 →
    `Temperatura: 0,0 °C`; umidità 90.6 → `Umidità: 91 %`; precipitazioni 12 → `Precipitazioni: 12,0 mm`.
  - `test_parametri_estranei`: `{"localita": "Pordenone", "giorni": 3}` → stesso risultato completo.
  - `test_definizione`: `DEFINIZIONE_METEO` uguale al dizionario della sezione «Definizione per il
    modello» della specifica (copiato nel test).
